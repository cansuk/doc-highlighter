This file exists to try Notestark on. The text in it is deliberately made of different structures: paragraphs, a list, a table, code and a quote.

Selection inside one element

This whole paragraph sits inside a single text node. It is the easiest case for a highlight: the selection starts and ends inside the same element, so the anchor is one pair of offsets. Try selecting this sentence from beginning to end.

Selection across elements

The hard case is this: when a selection starts in one element and ends in another, the DOM wrapping approach produces nested structures and breaks the page. The CSS Custom Highlight API solves it without touching the DOM at all. Start dragging from the middle of this paragraph and stop at the second item of the list below.

Repeated text

The sneakiest problem in anchoring: telling which occurrence was highlighted when the same text appears several times on a page. The word status appears three times in the rows below, in three different contexts.

FieldDescription
statusThe application's current status

A highlight that does not land in the same place when the page is reloaded is not a highlight. It is a colour someone saw once.

Long text

Everything from here down is filler, so that there is a region which needs scrolling. A highlight ending up outside the visible area after a reload — where the reader cannot find it — is a separate UX problem from whether it was restored at all; a "go to highlight" navigation may be needed later.
