# Changelog

What each version brought, and where it is worth saying, why.

Versions before 0.8.0 predate the Web Store submission; 0.8.0 is the first published
release.

| Version | What changed |
|---|---|
| **0.16.0** | The extension became **Notestark** — the browser side of the note application at `notestark.com`. The store title, the promo tiles and the privacy policy are regenerated from one source rather than edited by hand. **Deliberately unchanged:** the storage keys (`doc:`, `hash:`, `dhPalette`, `dhPanelPrefs`, `dhTranslate`), the CSS prefixes (`dh-`, `data-dh-`) and the diagnostics handle. Renaming those would orphan every highlight anyone had already saved, in exchange for fixing an internal name no reader ever sees. Product naming and internal naming are different things and only one of them moved |
| 0.16.0 | **Recent tab** — opening the menu shows what you marked, newest first, grouped by where you marked it: the site, or the filename for a local document. Each group folds away, and everything marked in one place can be cleared in one step (behind a confirmation). Nothing new is stored; the records are already keyed by document, so this reads them — a second list would only be something that could fall out of step. Clearing removes the hash index alongside the record: left behind, it would let a renamed file resurrect a document that no longer exists |
| 0.16.0 | **The eraser respects the selection.** It could only wipe the whole document before, which made it a button you had to be brave to press. With text selected it now clears only the selection; the two-step confirmation stays where it is actually warranted — on the one that takes everything. The tooltip says which of the two is armed |
| 0.16.0 | **A note's origin is kept in the data and shown.** A note that came from a translation is a blue circle; one you wrote is an amber folded corner. Colour alone would have been a weak label — two dark cool tones are exactly the pair colour vision deficiency flattens — so the shape carries it too. A note you wrote has no origin field at all, so every note that already existed lands on the right side without a migration |
| 0.16.0 | **The dot takes its mark's colour**, mixed towards the ink so it can be seen on that colour — a marker on yellow text has to be darker than the yellow. The mix is measured: a first attempt landed at 2.70:1, under WCAG 1.4.11 (3:1 for a non-text UI component); a straight mix at 0.70 reaches 3.86:1. The panel now draws the same three cases the page does — a missing branch had been sending a colourless mark to the underline chip, so a translation note showed red in the panel and blue on the document |
| 0.16.0 | **The pulse can be switched off.** The seizure threshold is three flashes per second and this is 0.67 Hz, far under it. The criterion it did cross is **WCAG 2.2.2** (Pause Stop Hide), which asks for a way to stop motion lasting more than five seconds: three cycles plus the stagger reached 5.4s. The stagger is capped at 400 ms (4.9s total) **and** it is a setting, because motion is not only a seizure question. Default on; `prefers-reduced-motion` still wins without anyone finding the switch. Three of the tests read the numbers out of the source and check them against the thresholds, so the limits are enforced rather than commented |
| 0.16.0 | The panel now **measures** when it reserves space. A margin on `html` is dropped by the browser whenever the root element's width is not auto — over-constrained, with no error and no warning — and the panel ends up on top of the text. The rule is written, read back, and swapped to `body` if the root refused it. Measured on MDN: `html` 0px, `body` 332px |
| 0.15.0 | **Translate a passage, on the device** — Chrome's built-in Translator. That is the only reason this feature exists: sending a passage to a translation service would break the promise the rest of the extension is built on, and would contradict both the privacy policy and what was declared to the store. The language button on the selection toolbar shows the target and translates on click; the caret beside it opens a short target list, because the decision gets made next to the passage. A translation can be **kept as a note** — a translation you want to keep *is* a note about that passage. No list of language names exists anywhere in the project: codes are stored and `Intl.DisplayNames` renders them in the reader's own language, so thirty languages cost no translation work. Needs Chrome 138+ on desktop |
| 0.14.0 | **Right-click menu** — what the toolbar and panel already do, without moving the pointer off the passage. The menu lives in the service worker, which can see neither the selection nor the page, so every item is carried out by one command sent to the content script. Selection-dependent items are declared selection-only, and the menu is limited to `file://` and http(s) so it never appears where nothing can answer it. Adds the `contextMenus` permission. **The tests found a real defect while covering it:** writing a note used to create the mark with a single space as a placeholder and fill it in afterwards; the space never survived (a note is trimmed, and an empty one becomes `undefined`), so the note command produced nothing at all — and cancelling left an invisible record behind with no colour, no underline and no note |
| 0.13.1 | **The colour picker opens on the first click.** The row was a `<button>` with the colour `<input>` inside it. Interactive content inside a button is invalid HTML and the button swallowed the click: measured in a browser with all three candidate structures side by side, the input never received it at all. That is why it took seven or eight tries — each was a near miss on the input's own box rather than a click the row forwarded. A `<label>` forwards a click to the input it wraps, natively |
| 0.13.0 | **The menu redesigned in the product's own language.** The previous one was a copy: left icon rail, generic icons, the same shape as the extension it was modelled on. It is built from what this product is — a highlighter. The active tab is not a pill but a **yellow stroke**, drawn slightly crooked with uneven corners, overshooting the word the way a real one does. Colours are shown as strokes over their own names rather than as swatches, because a highlighter is judged by how text looks *through* it and a square cannot show that. Underline is drawn as what it is: a rule under the text, not a wash behind it |
| 0.12.0 | **Quick menu with a customisable palette.** The popup was one column of buttons; it became four tabs behind an icon rail. The palette can be changed: the defaults were measured rather than chosen by eye, so the picker shows the contrast against the ink as you go and flags anything under WCAG AAA — a custom colour is the user's call, but "my highlights are unreadable" should not be discovered later and blamed on the extension. Changes land in storage and every open page repaints without a reload |
| 0.11.0 | **Markdown preview and a Notes tab.** A local `.md` file renders automatically — headings, code, lists, tables, quotes — with a toggle back to the source. This is the one place the engine deliberately rewrites the document, and that is not a contradiction: the "never touch the DOM" rule exists to stop *incidental* mutation from breaking anchors, and switching view is not incidental. The cost is handled: anchors are quotes and offsets into the flattened text, and rendering changes that text (`## Title` becomes `Title`), so a mark covering markdown syntax will not resolve in the rendered view — it is not lost, it is kept as an orphan and returns when the view is switched off. The renderer is ours: remote code is allowed by neither the CSP nor what was declared to the store. A `.md` file is untrusted input, so HTML is escaped first and link schemes are filtered — tested with a script tag, an inline handler and a `javascript:` URL |
| 0.10.2 | The note dot was flattened — the white ring and the shadow are gone. On a dark page the ring read as a frame stuck onto the text rather than as part of the mark. The dot is flat colour now, slightly smaller, and shows its open state by darkening and growing instead of by an outline. The one ring kept is `:focus-visible`, where showing the ring *is* the point |
| 0.10.1 | The panel handle is drawn in the brand yellow with a glow. Its previous form used the panel's own muted colours and disappeared on a busy page. The width change propagates to the reserved page margin on its own — both read the same constant |
| 0.10.0 | **Sticky notes** attached to a highlight. A note is not a separate object but a field on the highlight record, so the existing anchor system carries it: when the document changes, the note travels with the text. A small dot appears at the end of an annotated passage; clicking it opens the card |
| 0.9.0 | **Navigator panel** — docks to the left or right edge, opens and closes. One tab is the document outline, another lists every highlight; clicking a row scrolls to it and draws a brief frame. In raw `.md` files the headings are read out of the `# ` syntax, because there are none in the DOM. Theme and panel side are remembered |
| 0.8.1 | `minimum_chrome_version: 105` — older Chrome now refuses to install it. Before this it installed and then silently did nothing, because `CSS.highlights` was absent |
| 0.8.0 | **Clear all** button — eraser icon, two-step confirmation. Removes the storage record as well |
| 0.7.0 | **Colour and underline can be combined** — they became separate fields, and older records migrate automatically. The toolbar is semi-transparent (the text behind it stays readable) and shows the active style |
| 0.6.0 | **Six colours** (blue, orange and purple added) — the palette was measured for contrast and colour blindness. The toolbar no longer overflows the viewport |
| 0.5.4 | **Working on all sites actually turned on** — the `*://*/*` permission was being silently dropped by an origin filter. Verified end to end in the browser |
| 0.5.3 | Diagnostics bridge (postMessage) so automation can read the content script's state |
| 0.5.2 | Record recovery chain: a way out of the dead end left by a half-written persistent registration |
| 0.5.1 | Race fix: `Duplicate script ID` meant the dynamic content script registration was never created at all |
| 0.5.0 | **iframe support** — pages that render their content in a frame. In frames the key is the content hash rather than the URL |
| 0.4.0 | **Working on all websites** — one click from the popup. Safari added to the roadmap as Stage 2 |
| 0.3.0 | Diagnostics logs turned off (can be switched on), `Extension context invalidated` caught, re-anchoring via MutationObserver, storage schema became URL-primary |
| 0.2.0 | **Highlight engine** — selection, colour/underline, persistence, restoration. `optional_host_permissions` for websites |
| 0.1.0 | File-scheme access flow, icon pipeline, i18n |
